Deception & Threat Research

Rust Telnet Honeypot: What IoT Botnets Do After Login

A telnet honeypot in Rust on Google Cloud, with a fake shell that records what bots do after logging in and never runs anything they send.

  • Recorded 2,450 connections from 364 IPs in 86 hours. 481 logins sent 1,772 commands, and 13 malware download attempts made zero outbound connections.
  • Mapped the post-login playbook to MITRE ATT&CK: router-menu escapes, BusyBox checks, writable-folder probes and droppers for several CPU types.
  • Each layer assumes the last one failed: fixed replies the compiler enforces, a noexec systemd sandbox, and outbound traffic denied at both the host and cloud firewalls.

Detection Engineering

Playbook Defense: Honeypot Findings as Alerts, Allowlist and Trap

16 Sigma rules mapped to each step of the IoT botnet playbook (MITRE ATT&CK), a GCP firewall allowlist in Terraform, and an internal NAS decoy where any connection is an alert.

  • Wrote 16 Sigma rules, one or more for every step from default-password login to cleanup. CI checks every rule against MITRE ATT&CK and converts them to Splunk searches, and validates the Terraform, on every push.
  • Admin ports answer only allowlisted addresses such as the VPN and Identity-Aware Proxy, telnet is denied to everyone by default, and IoT devices can reach only approved servers. One file feeds both the firewall and the alerts, so they never disagree.
  • The NAS decoy runs the honeypot's fake shell with no public IP. Nothing legitimate touches it, so any connection is a high-confidence alert.

SOC Home Lab: Azure Honeypots + Sentinel

Three internet-facing honeypots feeding Microsoft Sentinel, used to write and test real detections against real attackers.
